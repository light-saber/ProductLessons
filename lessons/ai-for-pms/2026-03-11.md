# AI Tokens & Context Windows: The Currency and Memory of LLMs

**Topic:** AI Tokens & Context Windows  
**Date:** March 11, 2026  
**Cycle:** 3 | Lesson 1

---

## 1. Technical Explanation

Tokens are the atomic units LLMs process — roughly ¾ of an English word. "Walmart" is 1-2 tokens; a page of text is ~400 tokens. Every API call has an **input** (prompt) and **output** (completion) token count, and you pay for both.

The **context window** is the model's working memory — everything it can "see" in one call. Current limits (March 2026):

| Model | Context Window | Input $/1M tokens | Output $/1M tokens |
|-------|---------------|-------------------|-------------------|
| Gemini 3 Pro | 10M tokens | $2.00 | $12.00 |
| GPT-5.3 Instant | 400K tokens | ~$2.50 | ~$10.00 |
| Claude Opus 4.6 | 200K (1M beta) | $3.00 | $15.00 |
| Gemini 2.5 Flash | 1M tokens | $0.30 | $2.50 |

Context windows have 100x'd in two years, but bigger ≠ better. Retrieval accuracy degrades in the middle of very long contexts ("lost in the middle" effect), and cost scales linearly with input tokens. Output tokens cost 3-5x more than input — a critical design constraint.

---

## 2. Simple Explanation

Think of tokens as **words the AI buys with a meter running**. Every question you ask and every answer it gives ticks the meter. The context window is like a **whiteboard the AI can write on** — once it's full, old stuff gets erased. A bigger whiteboard means the AI remembers more of your conversation, but you're paying for every square inch it reads. The real cost trap? Long answers cost way more than long questions.

---

## 3. Real Example

When Walmart's search team evaluates adding AI-generated product descriptions, the PM must calculate: 500K products × ~200 output tokens per description = 100M output tokens. At Gemini 2.5 Flash rates ($2.50/1M output), that's **₹21,000** — cheap. At Claude Opus rates ($15/1M), it's **₹1,26,000**. The PM chose Flash for bulk generation and Opus only for premium categories needing nuanced copy. Token economics directly drove the model routing architecture.

---

## 4. Key Takeaways

- **1 token ≈ ¾ word.** Always estimate both input AND output tokens for cost modeling.
- **Output tokens cost 3-5x more than input** — design prompts that get concise answers.
- **Bigger context ≠ better results.** Accuracy drops in ultra-long contexts; use RAG for precision.
- **Model routing saves money.** Use cheap models for bulk, expensive ones for quality-critical paths.
- **Context windows are exploding** (10M tokens now available), but your budget still prefers targeted retrieval over stuffing everything in.
