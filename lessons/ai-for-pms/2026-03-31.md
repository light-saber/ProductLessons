# Model Quantization: How to Shrink AI Without Breaking It

**Topic:** Model Parameters & Quantization (4-bit, 8-bit, GGUF)  
**Date:** 2026-03-31  
**Cycle:** 2, Lesson 3 of 12

## 1. Technical Explanation

Every LLM stores billions of **weights** — numerical values that encode what the model "knows." By default, each weight uses 16 bits (FP16), so a 70B-parameter model needs ~140 GB of memory — far beyond a single GPU.

**Quantization** reduces each weight's precision. Key formats:

- **FP16/BF16 (16-bit):** Full quality, 2 bytes per parameter. Llama 3 70B → 140 GB.
- **INT8 (8-bit):** Halves memory with ~1% quality loss. Same model → 70 GB.
- **INT4 (4-bit):** Quarters memory, ~3-5% quality loss. Same model → 35 GB — fits on a single 48 GB GPU.
- **GGUF:** A file format (from llama.cpp) that packages quantized models for CPU/hybrid inference. Common variants: Q4_K_M, Q5_K_M, Q8_0 — the number indicates bits.

Two main approaches: **post-training quantization** (GPTQ, AWQ — requires a calibration dataset, better accuracy) and **on-the-fly quantization** (bitsandbytes — zero calibration, just load and go). The tradeoff is always precision vs. memory vs. speed.

## 2. Simple Explanation

Think of a high-resolution photo. The original might be 50 MB — great quality, but heavy. You can compress it to 12 MB JPEG and barely notice the difference. Compress further to 5 MB, and you start seeing some blur, but it's still perfectly usable.

Quantization does the same thing to AI models. A full-size model might need a ₹25 lakh GPU server. After "compressing" it to 4-bit, it runs on a ₹1.5 lakh gaming PC — with surprisingly little quality loss. The model still knows everything; it just stores that knowledge more efficiently. For most product use cases, users can't tell the difference.

## 3. Real Example

When Meta released Llama 3 70B, it was too large for most teams to self-host. Within days, the community released GGUF quantized versions (Q4_K_M) that ran on a single consumer GPU. Companies like Walmart could now evaluate running a 70B model on-premise for sensitive retail data — price optimization, inventory forecasting — without sending data to external APIs. The PM decision: instead of paying $0.003/1K tokens to an API provider, they could self-host the quantized model at a fraction of the cost, keeping proprietary pricing data in-house. The quality drop on structured tasks like JSON extraction was under 2%.

## 4. Key Takeaways

- **Quantization trades precision for efficiency** — 4-bit models use 4× less memory than FP16 with manageable quality loss
- **GGUF is the standard format** for running models locally (CPU + GPU hybrid inference via llama.cpp)
- **Not all tasks degrade equally** — structured extraction and classification survive quantization well; creative writing and nuanced reasoning suffer more
- **This unlocks self-hosting economics** — a PM deciding between API costs and on-premise deployment must understand quantization tradeoffs
- **Always benchmark your specific use case** — never assume quality loss numbers from general benchmarks apply to your domain
