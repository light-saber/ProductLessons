# AI Tokens & Context Windows: The Memory Budget Every PM Must Understand

**Topic:** AI Tokens & Context Windows  
**Date:** 2026-03-27  
**Cycle:** 2, Lesson 1 of 12

---

## 1. Technical Explanation

A **token** is the atomic unit LLMs process — roughly ¾ of an English word. "Walmart" is 1 token; "recommendations" is 3. Every API call has an **input token count** (your prompt + system instructions + conversation history) and an **output token count** (the model's response).

The **context window** is the total token budget for a single interaction — input + output combined. Current benchmarks: Claude Opus 4.6 and Sonnet 4.6 offer **1M tokens** (~750K words), GPT-5.4 sits around **256K tokens**, and Google's Gemini 2.5 Pro reaches **1M tokens**. But bigger isn't always better — cost scales linearly with tokens consumed (Claude Opus: $5/M input, $25/M output), and attention quality degrades in the middle of very long contexts ("lost in the middle" problem).

**Max output** matters separately: Claude Opus caps at 128K output tokens, Sonnet at 64K. If your feature needs a 50-page report generated in one shot, output limits constrain you more than context windows.

---

## 2. Simple Explanation

Think of a context window like a **whiteboard in a meeting room**. Everything you write on it — the agenda, notes, questions, answers — must fit. Once the whiteboard is full, you either erase old notes (losing context) or get a bigger board (more expensive model).

Tokens are like **individual sticky notes** on that whiteboard. Short words take one sticky note, long words might take two or three. The model reads every sticky note on the board before responding, so more notes = slower and costlier responses.

A PM's job: figure out how much whiteboard your feature actually needs, and whether you're paying for empty space.

---

## 3. Real Example

Consider a **Walmart customer support chatbot** handling return requests. Each conversation might run 20 back-and-forth messages (~2K tokens), plus the system prompt with return policies (~1K tokens), plus the customer's order history pulled via RAG (~500 tokens). Total: ~3,500 tokens per session.

Using Claude Haiku at $1/M input tokens, that's **$0.0035 per conversation**. But if a PM naively stuffs the entire product catalog (500K tokens) into context "just in case," the same conversation costs **$0.50** — a 143x increase with minimal quality improvement. The smart PM decision: use RAG to inject only the relevant 3-5 products, keeping context lean and costs predictable at scale.

---

## 4. Key Takeaways

- **1 token ≈ ¾ of an English word.** Always estimate your feature's token budget before choosing a model.
- **Context window ≠ free memory.** You pay per token, and quality can drop in very long contexts.
- **Output limits matter separately.** Check max output tokens if your feature generates long-form content.
- **Lean context wins.** Use RAG or summarization to keep context focused — don't dump everything in "just in case."
- **Cost math is simple:** tokens × price-per-million. Run it before your sprint planning, not after your AWS bill arrives.
