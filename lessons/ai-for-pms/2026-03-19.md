# Latency, Throughput & Cost: The Iron Triangle of AI Inference

**Topic:** Latency, Throughput & Cost Optimization  
**Date:** 2026-03-19  
**Series:** AI for PMs

---

## 1. Technical Explanation

Every AI API call has three competing metrics: **latency** (how fast one response arrives), **throughput** (how many requests/second the system handles), and **cost** (price per token or per query).

LLM inference has two phases. **Prefill** processes your entire prompt in one compute-heavy pass — this determines Time to First Token (TTFT). **Decode** generates tokens one-by-one and is memory-bandwidth-bound, not compute-bound. This distinction matters because different optimizations target different phases.

Key techniques shipping in production today:

- **Speculative decoding:** A small "draft" model predicts several tokens; the large model verifies them in one parallel pass. Result: 2-3× faster generation, zero quality loss.
- **Continuous batching:** Instead of waiting to fill a batch, the serving engine slides new requests into GPU slots as others finish — boosting throughput ~40%.
- **KV cache + PagedAttention:** Caches attention state across tokens; PagedAttention (vLLM) manages this memory like virtual memory pages, preventing waste.
- **Model routing:** Send simple queries to cheaper models (GPT-5.4 nano at $0.20/M input tokens), escalate complex ones to flagship models ($2.50/M). Savings: 30-60%.
- **Prompt caching:** Repeated system prompts get cached at 90% discount (e.g., $0.25 vs $2.50/M on OpenAI).

The metrics to track: TTFT, tokens-per-second (TPS), cost-per-query, cache hit rate, and GPU utilization.

## 2. Simple Explanation

Think of a restaurant kitchen. **Latency** is how long *your* order takes. **Throughput** is how many orders the kitchen handles per hour. **Cost** is what you pay the chef.

A faster chef (better GPU) helps, but the real wins come from smarter workflows. Speculative decoding is like a junior cook pre-plating dishes that the head chef approves in one glance. Continuous batching is the kitchen working on 20 orders simultaneously instead of finishing one before starting the next. Model routing is sending simple sandwich orders to the fast-food counter and reserving the head chef for complex dishes.

The takeaway: you don't always need a bigger kitchen — you need a smarter one.

---

## 3. Real Example

At **Walmart**, consider the AI-powered customer support assistant handling millions of queries daily. Most questions ("where's my order?", "return policy") are simple — route them to a nano-class model at $0.20/M tokens. Complex complaints needing nuance go to a flagship model at $2.50/M.

Add prompt caching for the shared system prompt (product catalog context, policies) — that's a 90% cost reduction on repeated input. Enable continuous batching during peak hours (Black Friday) to handle 10× traffic without 10× GPUs.

A PM who understands this iron triangle doesn't just say "make it faster" — they specify *which* metric matters for *which* user journey and design the routing logic accordingly.

---

## 4. Key Takeaways

- **Latency ≠ throughput.** Optimizing one can hurt the other — know which matters for your feature.
- **Model routing is the highest-ROI PM decision.** Match model tier to query complexity; save 30-60% with zero quality loss on simple tasks.
- **Prompt caching is free money.** If your system prompt is stable, cache it — 90% input cost savings.
- **Track TTFT and TPS separately.** Users feel TTFT (time to first token); your infra team cares about TPS (throughput).
- **The decode phase is memory-bound, not compute-bound.** More GPUs won't help if your bottleneck is memory bandwidth — speculative decoding will.
